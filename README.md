## 这是什么

## 鉴权（2026-10-11 上线）

每人口令方案：口令存 Worker secret（`AUTH_TOKEN_HELEN` / `AUTH_TOKEN_ALAN`）；`POST /api/login` 验口令后发 30 天 session（存 KV）；`/api/chat` 强制验 `Authorization: Bearer <session>`，身份取自服务端会话，前端传的 `user` 参数被忽略。原前端身份切换按钮已移除，页面为口令登录门。

## 防编数硬规则（2026-10-13 上线，基础版简单修法）

起因：晓晖账号问 BE 当前 pt1/pt2，模型误把家里 pt-levels 口径的短期支撑/压力当成分析师目标价，并给出自称截至 2024 年 6 月的旧数据。

改动（仅改 `worker.js` 的 `SYSTEM_PROMPTS`，已部署，HTTP 200）：
- 晓晖：PT1/PT2 在这里指家里 pt-levels 的短期支撑位/短期压力位（成交量分布算的），不是分析师目标价；没有实时行情、没有接任何价格接口，被问当前价/当前 PT1/PT2/财报数字等实时数据时，必须明说“我没有实时数据，查不到”，不编数字、不编日期、不拿旧数据当当前数据；不知道就说不知道。
- Helen：同样加“没有实时行情、被问实时数据必须明说查不到，不编数字、不编日期、不拿旧数据当当前数据”。

## 可继续优化的地儿（未做，仅记录，待测试后决定）
1. **仅 prompt 约束，无强制校验**：Gemini 仍可能违反硬规则（尤其被追问时）。若测试中仍编数，考虑：Worker 侧后处理校验（例如检测到“当前价”类回答含数字时拦截/改写）、或换更强模型、或把“查不到”做成确定性分支（Worker 直接拦截实时数据类问题，不发给模型）。
2. **无实时行情接口**：当前价、当前 PT1/PT2 仍需去行情软件 / pt-levels 站查。后续可选：接价格 API；或 Worker 在问 PT 时自动返回 pt-levels JSON 当天数值（需先定好 PT1/PT2 与 JSON 字段的对应关系，以及是否只返回数值、不让模型发挥）。
3. **PT 定义只写在 prompt 里，未接数据**：模型现在只知道定义，给不出当天具体数值。问“BE 当前 pt1/pt2 是多少”时，正确回答应是“我没有实时数据，查不到，去 pt-levels 站看”，而不是给数。
4. **无记忆**：退出清屏、后端不存历史，新登录从零开始。两人测试阶段先这样；后续可审计记忆层（来源/引用查看/纠正）再议。
5. **无来源引用**：回答不带来源，需人工核对。交易类回答尤其要核对实时源。
6. **格式差异预期存在**：Gemini（onlymanes）与 Muse（此处）模型不同，格式不同是预期的，未统一。
